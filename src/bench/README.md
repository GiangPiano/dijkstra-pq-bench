# Benchmark Suite (`src/bench/`)

This directory houses the benchmarking harnesses, synthetic graph generation tooling, and analysis scripts for evaluating priority queue implementations under Dijkstra's Single-Source Shortest Path (SSSP) algorithm.

---

## Directory Organization

```
src/bench/
├── bench0/                   # Experiment 0: Wall-Clock Runtime Benchmarking
│   ├── bench0.h              # Header-only microbenchmarking framework (derived from ubench.h)
│   └── plot0.py              # Visualizer: generates runtime SVGs and Markdown/LaTeX tables
├── bench1/                   # Experiment 1: Microarchitectural Profiling (perf stat)
│   ├── bench1.c              # C runner with warm-up loop & isolated perf-stat execution
│   ├── bench1.py             # Orchestrator: runs taskset -c 0 perf stat across all variants
│   └── plot1.py              # Visualizer: generates L1 miss rate, IPC SVGs & summary tables
├── gen.py                    # Procedural synthetic graph generator (C code + checksums)
└── README.md                 # This documentation
```

All generated visual artifacts and tables are written to:
- `report/figures/runtime/` — Wall-clock runtime plots and summary tables
- `report/figures/perf/` — Hardware counter plots and microarchitectural summary tables

---

## Experiment 0: Wall-Clock Runtime Benchmarking

Measures the elapsed execution time of Dijkstra's algorithm across heap implementations under both **Explicit Decrease-Key** and **Lazy Insertion** modes.

### 1. Build Binaries
```bash
make build
```
Builds `bin/binary`, `bin/pairing`, `bin/fibonacci`, `bin/brodal-okasaki`, and `bin/stub`.
Any missing synthetic graph C files under `data/src/` (`tiny_dense.c`, `small_med.c`, `mod_sparse.c`, `big_sparse.c`) are automatically generated by `src/bench/gen.py`.

### 2. Run Benchmarks
To run all test suites across all heap variants:
```bash
make tests
```
Or run an individual variant directly:
```bash
./bin/binary --output=data/out/binary.csv
./bin/pairing --output=data/out/pairing.csv
./bin/fibonacci --output=data/out/fibonacci.csv
./bin/brodal-okasaki --output=data/out/brodal-okasaki.csv
```

### 3. Generate Runtime Plots & Tables
```bash
make plot
```
Invokes `src/bench/bench0/plot0.py`, producing:
- `report/figures/runtime/runtime_tiny_dense.svg`
- `report/figures/runtime/runtime_small_med.svg`
- `report/figures/runtime/runtime_mod_sparse.svg`
- `report/figures/runtime/runtime_big_sparse.svg`
- `report/figures/runtime/speedup_lazy_vs_decrease_key.svg`
- `report/figures/runtime/benchmark_summary.md`
- `report/figures/runtime/benchmark_table.tex`

## Experiment 1: Microarchitectural Profiling (`perf stat`)

Explains mechanistically why asymptotic complexity fails to predict physical wall-clock performance by measuring CPU hardware cache behavior and pipeline efficiency.

### Hardware Counters Monitored
- **L1-D Cache Miss Rate**: $\frac{\text{L1-dcache-load-misses}}{\text{L1-dcache-loads}} \times 100\%$ (Pointer indirection cost)
- **Last-Level Cache (LLC) Miss Rate**: $\frac{\text{LLC-load-misses}}{\text{LLC-loads}} \times 100\%$ (RAM round-trips)
- **Branch Misprediction Rate**: $\frac{\text{branch-misses}}{\text{branch-instructions}} \times 100\%$ (Pipeline stalls)
- **Instructions Per Cycle (IPC)**: $\frac{\text{instructions}}{\text{cycles}}$ (Execution throughput)

### Test Configurations
Fixed $N = 50{,}000$ vertices:
1. **Sparse**: $\bar{d} = 4$ ($M = 200{,}000$ edges)
2. **Dense**: $\bar{d} = 128$ ($M = 6{,}400{,}000$ edges)

### 1. Build Profiling Binaries
```bash
make perf-build
```
Produces `bin/perf_binary`, `bin/perf_pairing`, `bin/perf_fibonacci`, `bin/perf_brodal-okasaki`.

### 2. Run Hardware Counter Profiling
```bash
make perf-run
```
Or run `src/bench/bench1/bench1.py` directly with custom CPU pinning:
```bash
./src/bench/bench1/bench1.py --core 0 -o data/out/perf/hardware_counters.csv
```

> **Note on Permissions**:
> Linux hardware counters require access permissions. If `perf stat` returns permission errors:
> ```bash
> sudo sysctl -w kernel.perf_event_paranoid=0
> ```

> **Note on Brodal-Okasaki Dense Decrease-Key**:
> The functional implementation incurs an $O(M \cdot N)$ runtime on dense graphs ($\sim 3.2 \times 10^{11}$ operations), which is skipped automatically in `bench1.py` to prevent multi-hour hangs.

### 3. Generate Microarchitectural Plots & Tables
```bash
make perf-plot
```
Invokes `src/bench/bench1/plot1.py`, producing:
- `report/figures/perf/l1_cache_miss_rate.svg`
- `report/figures/perf/ipc_comparison.svg`
- `report/figures/perf/perf_summary_table.md`
- `report/figures/perf/perf_summary_table.tex`

### 4. One-Shot Profiling Shortcut
```bash
make perf
```
Executes `perf-run` followed by `perf-plot`.

## Synthetic Graph Generation (`gen.py`)

`src/bench/gen.py` produces self-contained C source files containing CSR graph definitions along with a precomputed Python reference checksum for deterministic runtime correctness verification:

```bash
# Generate sparse graph (N=10,000, M=40,000, max weight=100, seed=42)
./src/bench/gen.py my_graph -n 10000 -m 40000 -w 100 -s 42 -o data/src/my_graph.c

# Generate graph using density percentage (-d in percent)
./src/bench/gen.py dense_graph -n 500 -d 40 -w 10 -s 67 -o data/src/dense_graph.c
```
